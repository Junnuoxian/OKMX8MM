OKMX8MM Demo2 新人操作手册

一、先别急着接硬件

刚接手时先在电脑上跑一遍。电脑端能跑通，再去碰开发板。

推荐顺序：

1. 跑 Demo2 总自检。
2. 看 A53 输出文件。
3. 看 M4 采集说明。
4. 再上开发板。
5. 最后接采集板和 CAN。

二、跑总自检

进入 Demo2 文件夹：

cd OKMX8MM-Demo2

执行：

.\scripts\check-demo2.ps1

正常现象：

A53 测试全部通过。
M4 测试全部通过。
最后出现 Demo2 self-check passed.

如果没有看到这个结果，先不要继续接线。

三、看 A53 输出

A53 是网关侧，负责保存、上传准备、CAN 准备和状态记录。

重点看：

runtime-data\a53-storage.jsonl
这里保存采集数据。

runtime-data\a53-mqtt-outbox.jsonl
这里放准备上传云平台的数据。

runtime-data\a53-can-trace.log
这里放准备发给矿车的 CAN 帧。

runtime-data\a53-status.json
这里看程序本次运行是否正常。

runtime-data\a53-heartbeat.jsonl
这里看程序有没有持续工作。

四、看 M4 采集部分

进入：

cd OKMX8MM-Demo2\m4

执行：

.\scripts\build-windows.ps1 -Test

重点看：

demo1\README.md
docs\board-test-guide.txt

M4 只负责采集。不要把 SD 卡、云平台、CAN 这些事情放到 M4 里。

五、开发板实测顺序

先测 A53：

1. 把 Demo2 放到开发板 Linux。
2. 进入 a53 文件夹。
3. 执行环境检查脚本。
4. 编译 A53 程序。
5. 运行模拟输入。
6. 看 SD 卡文件有没有生成。

再测 CAN：

1. 先接 CAN 工具，不要直接接矿车。
2. 启动 can0。
3. 用脚本发送 CAN 记录。
4. 看 CAN 工具有没有收到帧。

再测 MQTT：

1. 复制 MQTT 配置样例。
2. 填云平台参数。
3. 执行上传脚本。
4. 到云平台看数据有没有到。

最后测 M4：

1. 编译 M4 固件。
2. 按开发板手册启动 M4。
3. 看 UART4 调试串口。
4. 接 RS485 采集板。
5. 看 M4 有没有读到采集数据。

六、出问题时怎么查

先看 M4 有没有采到数据。
再看 A53 有没有收到数据。
再看 SD 卡文件有没有新增。
再看 MQTT 队列有没有新增。
再看 CAN 工具有没有收到数据。

不要同时查很多点。一次只查一段，比较容易找到问题。
