# Demo2 功能拆分记录

这个文件主要给接手代码的人看。看完后要知道：哪些事放在 M4，哪些事放在 A53。

## 项目要做什么

矿车上的传感器数据先进入外接采集板，再由 OKMX8MM 处理。

最终数据要走三路：

```text
一路保存到 SD 卡
一路上传到云平台
一路通过 CAN 发给矿车
```

## 为什么拆成两边

M4 更适合做采集，因为它简单、实时，适合固定节拍读数据。

A53 更适合做网关，因为它跑 Linux，处理文件、网络、CAN 工具和升级更方便。

所以分工是：

```text
M4：采集
A53：保存、上传、CAN、状态、升级预留
```

## 功能放在哪

| 功能模块 | 做什么 | Demo2 放哪边 |
| --- | --- | --- |
| 主流程 | 启动后按顺序初始化模块 | M4 和 A53 各有自己的入口 |
| 采集 | 读取模拟量和数字量 | M4 |
| 存储 | 把采集结果写成文件 | A53 |
| 云平台 | 准备并发送 MQTT 数据 | A53 |
| CAN | 给矿车发数据 | A53 |
| 心跳 | 记录程序是否还在工作 | A53 |
| 配置 | 管理运行参数 | A53 |
| 升级 | 预留后续 OTA 流程 | A53 |

## A53 使用的数据格式

```text
sequence,ai0,ai1,ai2,ai3,ai4,ai5,ai6,ai7,ai8,ai9,di_bits,speed_pulse_delta,speed_period_us
```

简单理解：

- `sequence` 是批次编号。
- `ai0` 到 `ai9` 是模拟量。
- `di_bits` 是数字量。
- `speed_pulse_delta` 和 `speed_period_us` 用来放转速相关数据。

如果现场只有 8 路模拟量，另外两路先填 0。后面确认硬件确实有更多输入，再改 M4 采集映射。

## 操作时按这个顺序

1. 电脑端跑 Demo2 总自检。
2. A53 单独跑模拟输入。
3. 看 A53 五个输出文件。
4. M4 单独跑主机测试。
5. A53 放到开发板 Linux 运行。
6. 测 SD 卡写入。
7. 测 CAN 工具收帧。
8. 测 MQTT 云平台。
9. 启动 M4。
10. 接外接采集板。
11. 打通 M4 到 A53。

先把每一步单独跑通，再连成完整流程。
